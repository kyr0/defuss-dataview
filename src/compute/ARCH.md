# Compute engine

`compile.ts` turns a descriptor into a frozen plan: it validates aliases and descriptor properties, interns expressions through `expressions.ts`, deduplicates measure states and builds `explain()`. `expressions.ts` owns the node vocabulary, validation limits and the per-execution evaluators. `aggregate.ts` owns the working-memory `Ledger` and the measure state columns. `group-table.ts` maps key tuples to dense group ids. `dates.ts` truncates instants and reads their parts in UTC or an IANA time zone, with integer calendar arithmetic and offsets from `Intl.DateTimeFormat`. `execute.ts` binds a plan to one snapshot, runs the per-batch kernel, finalizes groups and emits output; in partial mode it exports groups and states instead, and for a merge it folds partials in place of the scan. `partial.ts` owns the partial format: the descriptor fingerprint, export, validation of untrusted partials and folding them in. `aggregate.ts` owns each state kind's export and merge. `../compute.ts` is the public entry; `types.ts` holds the public types and output inference.

A plan never holds source state, so one plan runs on several sources concurrently; every execution builds its own evaluators, tables and state. Input reading, row validation, host fairness and cancellation between batches come from `readBatches` in `../stream/driver.ts`, which applies the stream executor's batch rules; session validation is shared with it. Existing key-cache columns reach compute only through the private registry in `../stream/field-capability.ts`, bound to the identity of the source's original `scan`, as for the other stream capabilities; compute leases them for one execution and never builds them.

Why native Maps for grouping, not a custom hash table: SameValueZero already gives the grouping equality for primitives, Dates and bytes get their own maps, and VERIFIED: a compact open-addressed table measured faster only at 100,000 single-number keys (documentation/COMPUTE_PERFORMANCE.md), below the plan's 10% gate inside a full plan (HYPOTHESIS there, with its falsifier).

Why one synchronous kernel per batch: the async generator around it holds the source and output protocol; keeping the row loop in a plain function lets the engine optimize it. VERIFIED: the change cut a 200,000-row scalar sum from 10.6 ms to 7.0 ms (2026-11-17).

Operations: no I/O, no timers beyond the driver's host yields, no logging. Security: plans are validated data; nothing is compiled from strings, and unsafe keys and non-plain alias objects are rejected. Privacy: an execution keeps no rows after it ends. Cross-execution state is the source's own key cache and, per time zone, bounded caches of UTC offsets and local day starts by day number, which hold no row values.

Why Intl for time zones, not Temporal: the package supports Node.js 20.19 and later, and Node.js 20 to 24 lack Temporal (20.20.2 and 24.22.3 checked), while `Intl.DateTimeFormat` reads the same time zone data. One `formatToParts` call took about 2.5 µs (Node.js 26.13.1, Apple M5 Max), so offsets are cached per UTC day; that is exact because no zone has two transitions less than a day apart (VERIFIED in `dates.ts`).

Why `each()` unwinds inside the group lookup, not as a stage before it: the row loop already holds the key tuple, so it looks up one group per element combination and updates the measures there. Groups then hold elements, never whole arrays, which group by identity, could not leave a worker in a partial, and would make one group per row.

Why the merge reuses the executor: HAVING, ordering, paging, output batching and the ledger stay one implementation, so merged and single-pass results come from the same finalization code. VERIFIED: `partial.test.ts` and `oracle.test.ts` compare merged parts with one pass and with the oracle.

Tests: `partial.test.ts` (key-range merges over DBSONL, exact sums, rejected and malformed partials, merge caps), `compute.test.ts` (descriptors, projection, scalar measures, views, lifecycle), `grouping.test.ts` (equality, caps, leases, strategies), `operators.test.ts` (every operator, validation errors, edge strategies), `dates.test.ts` (date operators against Temporal) and `oracle.test.ts`, which compares every plan kind with the independent evaluator in `tests/compute/oracle.ts`.
