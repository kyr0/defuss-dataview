Filter, sort and page big data grids & trees using one JSON descriptor that

runs in a page, worker or server turns a table into a tree counts rows, matches and pages never mutates your rows terminates on cyclic trees

defuss-dataview is the query engine behind defuss-shadcn's Big Data components. You describe filters, sorters, paging, tree expansion and selection as plain JSON; evaluateDataview() returns the requested page together with the counts your grid controls need. It touches no DOM, Node API or storage, so the same descriptor works in a component, a module worker and an API handler.

Try the live demo Run a descriptor

Built by Aron Homberg (kyr0) (opens in a new tab) – Open Source (MIT (opens in a new tab))

One descriptor

createDataview() validates filters, sorters, paging, tree options and UI metadata once and returns plain JSON state you can store, send to a server or restore after a reload.

Table or tree

Add tree: { idField, parentIdField } and the same query walks a hierarchy: matches keep their ancestors, siblings sort among themselves, and expansion is explicit state.

Exact counts

evaluateDataview() returns the page plus totalRows, matchedRows, visibleRows, pageCount and paging flags, so a grid never infers counts from a page's length.

Your rows stay yours

It never sorts or mutates the backing array, entries keep row object identity, and the patch helpers return the same array when nothing changes.

Zero dependencies

ESM and CommonJS with TypeScript declarations, plus a standalone browser module of 12.7 kB (4.6 kB gzip). No globals, subscriptions or storage access.

Hostile data terminates

Parent cycles, 30,000-level hierarchies, duplicate IDs and unsafe paths such as __proto__ have defined results instead of hangs, stack overflows or prototype access.

How it works

💡 One pass from descriptor to page

createDataview() validates a request once and returns plain JSON state. evaluateDataview(rows, view) then runs the same steps on every call, without caching or hidden state, and returns the requested page with its counts. A flat view skips the tree steps.

  1. 01

    List or tree

    Rows form a flat list or a tree: a list row is { "id": 4, "name": "Storage" }, a tree row also names its parent, { "id": 4, "parentId": 3, "name": "Storage" }, and adding tree: { "idField": "id", "parentIdField": "parentId" } to the query links every row to that parent. The first row with an ID wins, unknown parents become roots, and one edge per cycle is cut at its lowest input index.

  2. 02

    Sort

    Sorters compare in order and keep equal rows in input order. In a tree, the roots and each group of siblings sort separately, so children stay under their parent.

  3. 03

    Match

    Filters are ANDed. In a tree, the ancestors of every match are included (includeAncestors, default on), and their descendants on request (includeDescendantsOfMatch).

  4. 04

    Walk

    Tree views only. A preorder walk applies expansion and maxDepth; a collapsed ancestor hides its descendants even when they match.

  5. 05

    Page

    page × pageSize slices the visible sequence, so a page may begin at a child. Counts are taken before the slice.

Every entry is { row, meta }

row is your original object, never a copy, so it has a parent field only when your rows do: a tree row such as { "id": 4, "parentId": 3 } keeps its parentId, a list row needs none. meta says where the row sits.

depth
0 for a root; keeps its place in the hierarchy while filtering.
hasChildren
The source hierarchy has children here, even when none match.
isExpanded
Children show. A node stopped by maxDepth is not expanded.
isMatch
False for an ancestor shown only for a match.
isSelected
Its ID is in meta.selectedRowIds.
parentId
In a tree, the value of the row's parent field (the one tree.parentIdField names), also for a cycle edge that was cut. Always null in a list, even when the rows have a parent field.

        API
        
📚 Thirteen functions, plain data in and out

        
Views and rows go in; new views, rows or results come out. Rows keep their object identity, and the backing array is never sorted or mutated. The declarations ship as dist/index.d.mts and dist/index.d.cts; the source of truth is src/types.ts.

      

    


    

      

        
        
        
        
        
        
      


      

        

          

            
FunctionReturnsSemantics

            
              
createDataview(request = {})DataviewStateValidates and normalizes a request into plain JSON state. Malformed descriptors throw.

              
evaluateDataview(rows, view)DataviewResultThe requested entries plus counts and paging state.

              
applyDataview(rows, view)Array<{ row, meta }>The entries alone, as an array of { row, meta }.

              
updateMeta(view, updates)DataviewStateUpdates UI metadata without rebuilding query state; a semantic no-op returns the same view.

              
setSelectedRows(view, ids)DataviewStateReplaces the selection.

              
toggleSelectedRow(view, id)DataviewStateToggles one ID in the selection.

              
setLockedColumns(view, columns)DataviewStateDeduplicated, nonempty column names.

              
setExpandedIds(view, ids)DataviewStateSwitches to an explicit expansion list and clears exceptions.

              
toggleExpanded(view, id)DataviewStateToggles effective expansion. In expand-all mode it updates collapsedIds, so it needs no access to the rows. A no-op on flat views.

              
updateRows(rows, ids, updates, idField = 'id')rowsBatch shallow patches. Unchanged rows keep their identity; patch keys are literal property names.

              
addRows(rows, newRows, anchorId?, position = 'after', idField = 'id')rowsInserts before or after the first anchor; a missing anchor appends.

              
removeRows(rows, ids, idField = 'id')rowsRemoves matching rows, without deleting their subtrees.

              
setParent(rows, nodeId, parentId, idField = 'id', parentIdField = 'parentId')rowsAn immutable move. Rejects moves into itself, a descendant or an existing cyclic parent chain; an unknown parent is allowed, null detaches.

            
          

        

        
The patch helpers return the input array on a no-op. A controlled grid keeps rows and view apart: patch rows with updateRows or setParent, change the query with createDataview, change selection and expansion with the helpers, then evaluate again.

      


      

        
createDataview(request) takes a DataviewRequest. Every key is optional.

        

          

            
KeyTypeDefaultMeaning

            
              
filters{ field, op, value }[][]ANDed filters; see Filters & sorting.

              
sorters{ field, direction }[][]Sort keys in priority order. dir is an alias; direction wins. asc by default.

              
pagenumber0Zero-based safe integer. A page past the end returns no entries; it is not clamped.

              
pageSizenumbernoneA positive safe integer. Omit it to disable paging; page then has no effect.

              
idFieldstring'id' or tree.idFieldThe selection identifier. Graph identity always uses tree.idField.

              
meta{ selectedRowIds, lockedColumns }empty listsUI metadata. Extension fields on the view and on meta are kept.

              
treeDataviewTreeOptionsnoneMakes the view a tree; see Trees.

            
          

        

        

          

            Fields and paths
            
Fields are nonempty dot paths over own properties. __proto__, prototype, constructor, empty segments and empty paths are rejected, and inherited fields never match. Array indexes use dot syntax such as links.0.parent.

          

          

            When a filter changes
            
Build the next view with createDataview({ ...view, page: 0, filters: nextFilters }). Normalization validates the structure; filter values stay your references, which keeps equality semantics intact.

          

        

      


      

        

          

            
OperatorA cell matches when

            
              
eq, neqIt is (or is not) strictly equal to the value; object operands compare by reference.

              
gt, gte, lt, lteThe relational comparison holds. Null, missing, NaN and invalid-date cells never match.

              
inIt strictly equals an element of the array value. A value that is not an array matches nothing.

              
contains, startsWith, endsWithThe string operation holds. String operations are case-sensitive.

            
          

        

        

          

            Sort order
            
Equal values keep their input order. Mixed values sort in this ascending type order: booleans, numbers, BigInts, strings, valid Dates, other values, invalid numbers and dates, nullish values; descending reverses it. Numbers and Dates sort numerically, strings with the runtime's localeCompare, which can differ between host locales.

          

          

            Portable queries
            
JSON-compatible filter values serialize, but reference equality for object values does not survive a JSON round trip. Use scalar field predicates for queries you send to a server or store.

          

        

      


      

        

          

            
Tree optionBehavior

            
              
idField, parentIdFieldRequired dot paths that define graph identity.

              
expandedIdsOmitted: everything is open (expandAll defaults to true). An explicit [] collapses all. A nonempty list opens the listed IDs only, unless expandAll is explicitly true.

              
expandAllOpens everything except collapsedIds.

              
collapsedIdsExceptions, used only in expand-all mode.

              
maxDepthA nonnegative safe integer; roots have depth 0. Nodes it stops are not reported as expanded.

              
includeAncestorsInclude the ancestors of matches. Default true.

              
includeDescendantsOfMatchInclude the descendants of matching nodes. Default false.

            
          

        

        
Missing, null or unknown parents become roots; a self-parent renders as a root. Duplicate IDs keep separate rows, and parent references resolve to the first occurrence. To open everything again, use createDataview({ ...view, tree: { ...view.tree, expandAll: true, collapsedIds: [] } }).

      


      

        

          

            
FieldMeaning

            
              
entriesThe requested page; identical to applyDataview output.

              
totalRowsThe length of the backing array.

              
matchedRowsRows satisfying the filters, before ancestors or descendants are included and before collapsing.

              
visibleRowsIncluded rows that pass expansion and maxDepth, before paging.

              
page, pageSizeThe descriptor values.

              
pageCountceil(visibleRows / pageSize); unpaged, 1 when anything is visible, else 0.

              
hasPreviousPage, hasNextPagePaging flags, both false when unpaged. Past the last page, hasPreviousPage stays true when any page exists, so the app can recover.

            
          

        

        
Flat views have equal matchedRows and visibleRows. A tree can show more rows than match (included ancestors) or fewer (collapsed matches).

      


      

        

          

            
Canonical JSON identity
Selection, expansion, parent links and patches match IDs the same way.

            

              

                
Objects
Compare by JSON contents, independent of key order.

                
Arrays
Compare by contents in order.

                
Numbers, strings
Stay distinct: 1 is not '1'. -0 and 0 share an identity.

                
null, missing
Not selectable and not indexed as tree parents. Missing never aliases null.

              

            

          

          

            
Rejected identifiers
Lossy IDs fail instead of colliding.

            

              

                
Rejected
Non-finite numbers, explicit undefined, BigInts, Dates, functions, symbols, cycles, accessors, hidden properties, sparse or extended arrays.

                
Rows
Row IDs that are not JSON values are reported unselected. Other row fields may hold Dates, BigInts and so on.

                
Copies
Normalization copies selection and expansion IDs, so later caller mutation does not reach the view.

        Install
        
🧑‍💻 Add it to your app

        
Install it from npm, or import the browser module straight from a CDN. Then keep your rows and the view apart, or hand one prompt to your coding agent.

      

    

    

      

        
From npm

        
Bundlers resolve import … from 'defuss-dataview', CommonJS uses require('defuss-dataview'). The public types need only ES2022 libraries, with no DOM or Node ambient types.

        
      

      

      

      

        
In the browser, no bundler

        
dist/browser.min.mjs is one self-contained module. This page loads it exactly like this; browsers that support import-map integrity check the hash before the module runs.

        
      

    


    

      
Use it

      
Keep the rows and the view separately. Change the view with createDataview and the helpers, patch rows with the patch helpers, and evaluate again. The view is plain JSON, so it survives storage, a URL or a network hop unchanged.
